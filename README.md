# Kerberos System with Magma cipher

**Студент:** Гагалушко Савелий Викторович, gagalushko_sv_22, 4 курс 8 семестр, Компьютерная Безопасность, группа СДП-КБ-221, Дипломная работа

**Краткое описание:** Распределённая система аутентификации Kerberos с использованием шифра Магма (ГОСТ 28147-89), ролевой моделью (user/admin), взаимной TLS-аутентификацией (mTLS) и централизованным отзывом билетов. Проект демонстрирует защищённый обмен билетами, защиту от replay-атак и разграничение доступа к сервисам FileServer и MailServer.

## Требования
- Python 3.9+
- OpenSSL (для генерации сертификатов; но сертификаты уже есть в репозитории)
- Git

## Установка

1. Клонируйте репозиторий:
   ```bash
   git clone https://github.com/hahalushko/kerberos-diplom.git
   cd kerberos-diplom
   ```
2. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
   (если файл пуст – установка не требуется, но для Argon2 лучше выполнить `pip install argon2-cffi`)

## Запуск (в отдельных терминалах)

**Важно:** сначала скопируйте в эту же папку все закрытые ключи (`.key`), `master.key`, `tgs_key.bin` и файлы `client_db.json`, `service_keys.json`, `revoked_tickets.json` (они переданы отдельно).

Запускайте в следующем порядке:

1. `python db_server.py` (порт 9090)
2. `python as_server.py` (порт 8888)
3. `python tgs_server.py` (порт 8889)
4. `python service_server.py` (порты 8890, 8891)
5. `python client.py` – интерактивный клиент

## Администрирование

Все команды запускаются из той же папки, где лежат `admin.crt` и `admin.key`.

| Команда | Описание |
|---------|----------|
| `python admin_client.py list-users` | Показать всех пользователей и их роли |
| `python admin_client.py change-role john admin` | Сменить роль пользователя john на admin |
| `python admin_client.py delete-user alice` | Удалить пользователя alice (с подтверждением) |
| `python admin_client.py list-services` | Список зарегистрированных сервисов |
| `python admin_client.py revoke-ticket --ticket-id a1b2c3... --expires 1712345678` | Отозвать билет |

## Ролевая модель

- **user** – имеет доступ только к `MailServer`.
- **admin** – имеет доступ к `FileServer` и `MailServer`.

Права проверяются TGS на основе роли, полученной из DB.

## Важное примечание о сертификатах

Для успешного входа в систему **каждый пользователь должен иметь клиентский сертификат**, выпущенный тем же центром сертификации (CA), что и серверные сертификаты.  
**Common Name (CN) сертификата должно строго совпадать с именем пользователя**, под которым он регистрируется и входит.

Пример:
- При регистрации пользователя `alice` в папке проекта должны лежать `alice.crt` и `alice.key`, и CN в сертификате должен быть `alice`.

Без корректного сертификата:
- TGS откажет в выдаче Service Ticket (ошибка «клиент не предъявил сертификат» или «CN не совпадает»).
- Сервис также отклонит запрос.

**Поэтому перед регистрацией нового пользователя убедитесь, что его сертификат уже создан и помещён в папку проекта.**

Для администратора необходим сертификат с CN=`admin`, а также пользователь `admin` с ролью `admin` в базе (регистрируется через `client.py`).

## Тестирование уязвимостей

В проекте есть скрипт `vulnerability_tester.py`, который автоматически проверяет защищённость системы:

```bash
python vulnerability_tester.py
```

Он выполняет следующие тесты:
- Replay-атаки на AS, TGS и сервис
- Golden Ticket (подделка TGT)
- Silver Ticket (подделка Service Ticket)
- Обход прав администратора (отсутствие сертификата)
- Атака Kerberoasting
- Доступность файлов ключей
- Принудительность mTLS на TGS
- Подмену IP в TGT

Для работы скрипта необходимы те же сертификаты и ключи, что и для основного приложения (особенно `admin.crt`, `admin.key`, `user1.crt`, `user1.key`).

## Устранение типичных проблем

### Ошибка HMAC при доступе к сервису (access denied)
Если сервис возвращает `Ошибка HMAC` или `Недействительный билет`, вероятно, локальный ключ сервиса устарел.
**Решение:** удалите файлы `FileServer.key` и `MailServer.key` и перезапустите `service_server.py` – они будут пересозданы с актуальными ключами из DB.

### Admin rights required
Убедитесь, что:
- Вы зарегистрировали пользователя `admin` с ролью `admin` через клиент.
- В папке с `admin_client.py` лежат файлы `admin.crt` и `admin.key` с CN=admin.
- Запускаете команду из той же папки, где находятся эти файлы.

### Ошибка `[Errno 2] No such file or directory: 'ca.crt'`
Все сертификаты (`.crt`) и ключи (`.key`) должны лежать в одной папке со скриптами.

### Ошибка подключения к DB (Connection refused)
Запускайте `db_server.py` **первым** и дождитесь сообщения о запуске.

## Примечание о ключах

Все сертификаты (`.crt`) включены в репозиторий. Закрытые ключи (`.key`), `master.key`, `tgs_key.bin`, а также файлы `client_db.json`, `service_keys.json`, `revoked_tickets.json` **не включены** в репозиторий в целях безопасности. Они переданы преподавателю отдельно (архив с паролем). Скопируйте их в папку с проектом перед запуском.
